# Кабинет GlobalPost: что известно и как с ним связать CRM

Источник: документация и код проекта `kolosovskiy/ttn-mail-router` (спецификации API кабинета от
разработчика кабинета, 26.09–13.10.2026). Код самого кабинета ещё не изучен: он лежит локально
и в доступных репозиториях отсутствует. После изучения кода документ будет уточнён.

## Что такое кабинет

- Laravel (PHP), проект `cabinet-globalpost`, пишет разработчик компании (Макс).
- Центральная сущность — заказ (`orders`). Номер заказа GP (например `77350839`), накладная
  перевозчика (`contragent_number`), накладные мест (`order_multiple_parcels`), номер Новой почты.
- Дочерние заказы: `<GP>-мито` (пошлина) и `<GP>-доплата` (поздняя доплата перевозчика).
- У заказа есть менеджер, клиент (`client_id`), фирмы отправителя и получателя, вес и габариты,
  цена клиенту (`price*`) и себестоимость (`contragent_price*`) в UAH/EUR/USD, статьи затрат,
  битовый статус `status` и статус движения `way_status`, счёт клиенту и отметка оплаты.
- Перевозчики: FedEx, UPS, DHL, DPD, GLS, Новая почта, Raben. Своего API у перевозчиков для
  счетов нет, всё идёт через почту и документы.

## Существующее API кабинета

Все методы `POST`, JSON, `Authorization: Bearer <token>`, `Accept: application/json`.
Доступ разрешён только пользователям кабинета с ID 3 и 581 (служебный доступ робота).

| Метод | Что делает |
|---|---|
| `/api/orders/manager` | Найти один заказ по номеру GP, накладной, накладной места или номеру обращения |
| `/api/orders/manager/batch` | То же для списка до 200 номеров |
| `/api/orders/partner-payment` | Записать стоимость перевозчика (статья 31) |
| `/api/orders/partner-credit` | Уменьшить её по кредит-ноте |
| `/api/orders/duty` | Создать или дополнить заказ `-мито` |
| `/api/orders/surcharge` | Создать или дополнить заказ `-доплата` |
| `/api/orders/notification` | Замечание в карточку заказа (сейчас только расхождение веса) |

Ответ чтения содержит: номер, накладные, менеджера, клиента (имя), email отправителя и
получателя, вес и габариты, места, цены, страну назначения, перевозчика (`service`), Incoterms и
плательщика пошлины, статусы (`status`, `way_status`), счёт и оплату (`billing_details`),
дочерние заказы, `version` (хеш состояния). Запись ограничена 60 запросами в минуту.

## Что CRM может взять уже сейчас

1. **Заказ в карточке лида.** Менеджер вводит номер GP или накладной, CRM показывает статус,
   менеджера, вес, цену, страну, оплату. Источник — `/api/orders/manager`.
2. **Автопривязка переписки к заказу.** Клиент пишет «где моя посылка 876404485529»: CRM находит
   номер в тексте теми же шаблонами, что роутер (UPS `1Z…`, FedEx 12/15 цифр, DHL 10, DPD 14,
   UPU S10), спрашивает кабинет пакетом и привязывает диалог к заказу.
3. **Маршрутизация на ответственного.** Как в роутере: заказ найден, менеджер в кабинете есть,
   лид назначается этому менеджеру в CRM. Нужна связка имени менеджера в кабинете с
   пользователем CRM.

Для этого достаточно отдельного токена кабинета для CRM. Лучше завести отдельного пользователя
только на чтение, а не использовать токен робота: у пользователей 3 и 581 есть права записи
в финансы.

## Чего в кабинете нет и что нужно от разработчика кабинета

| Нужно CRM | Зачем | Предложение |
|---|---|---|
| Поиск клиента по телефону и email | Лид из Telegram или звонка Binotel сразу показывает «это клиент X, у него 14 заказов» | `POST /api/clients/search {phone|email}` → id, название, контакты, менеджер |
| Список заказов клиента | История отправок в карточке контакта | `POST /api/clients/{id}/orders` с пагинацией |
| Справочник статусов | `status` и `way_status` — коды без названий | Таблица кодов и названий на uk/sk/ru |
| События изменения заказа | Автоматически писать клиенту в Telegram или Viber «посылка прибыла на склад» | Вебхук в CRM при смене статуса или метод «изменённые с даты» |
| Создание заказа или черновика | Лид в CRM превращается в заказ без повторного ввода | `POST /api/orders/draft` с данными клиента, отправителя, получателя, мест |
| Расчёт стоимости | Менеджер считает цену прямо в CRM | Метод тарификации кабинета |
| Список менеджеров с id | Надёжная связка менеджеров кабинета и пользователей CRM | `GET /api/managers` |

- Значения битового `status` и кодов `way_status`.
- Есть ли в кабинете свои уведомления клиентам и рассылки, чтобы CRM их не дублировала.
- Как создаётся заказ и какие поля обязательны.
- Какие ещё API существуют помимо описанных роутером.
