# План развития

## Сделано (этап 1, каркас)

- Ядро: контакты с идентификаторами, воронки, лиды, диалоги, сообщения, звонки, задачи, заметки.
- Адаптеры: сайт, Binotel, Telegram, Viber, WhatsApp, Messenger, Instagram, email.
- Автоматизации с редактором в интерфейсе.
- Интерфейс: сводка, канбан, карточка лида, инбокс, контакты, задачи, звонки, настройки.
- Роли: администратор, программист, менеджер, оператор. Языки: uk, sk, ru.
- Тесты API и движка, сборка, docker-compose.

## Этап 2: запуск на реальных данных (ориентир 2–4 недели)

- Импорт из KeyCRM: контакты, лиды, история (через экспорт CSV или API KeyCRM).
- Шаблоны ответов в инбоксе и быстрые ответы.
- Уведомления менеджеру о новом лиде и сообщении: в интерфейсе (WebSocket) и в Telegram.
- Вложения: скачивание в своё хранилище (S3-совместимое), отправка файлов клиенту.
- Журнал действий пользователей (кто что изменил).
- Подключение WhatsApp Cloud API, когда понадобится (код готов, нужны токены Meta).

## Этап 3: аналитика и удобство (1–2 месяца)

- Отчёты: конверсия по этапам, по источникам, по менеджерам; скорость первого ответа; пропущенные.
- Click-to-call через Binotel API (звонок из карточки, исходящий с номера менеджера).
- Поиск по тексту переписки и записям (транскрибация звонков по желанию).
- Массовые операции и рассылки по сегментам (email, Viber Business Messages).
- Мобильная версия (адаптив уже есть, нужна доработка инбокса и карточки).

## Технический долг, который стоит закрыть до роста нагрузки

- Очередь для вебхуков и исходящих сообщений (BullMQ + Redis), повторные попытки отправки.
- Шифрование токенов интеграций в базе, если они будут настраиваться из интерфейса.
- Rate limiting на публичных вебхуках.
